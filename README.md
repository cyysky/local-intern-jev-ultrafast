# Intern-Decision

Run **Intern-Decision-4B** locally behind the same `/v1/systemone` API that
TypeSafe's Jev speaks, then drive Chrome with **Jev Ultrafast** using that local
model as the decision maker.

The checkpoint reads a page state plus a schema of named questions and returns an
answer distribution for every question in **one forward pass**. It never calls
`generate()` and never writes free-form text. Jev turns a browser page into that
state, asks, and executes the chosen operation; a separate small text model supplies
the words for `TYPE_TEXT`.

## Architecture

```text
Chrome (--remote-debugging-port=9222)
   |  CDP
Browser Harness daemon
   |
Jev Ultrafast  --->  inspector UI   http://127.0.0.1:8766
   |  POST /v1/systemone
intern_decision_server.py  (FastAPI, :8011)
   |
Intern-Decision-4B checkpoint  (transformers, one forward pass)
```

- `intern_decision_server.py` loads the checkpoint once, keeps it on one GPU, and
  serves Jev's request shapes over HTTP. It follows vLLM's
  `structured_server.py` contract, so a client that talks to a hosted Jev also
  talks to this server.
- `jev-ultrafast` is the browser agent. It observes the page, asks the decision
  model which operation and element to use, and executes it over CDP. Its inspector
  UI shows the element table, operation and target probabilities, and the trace.
- The decision model is the local endpoint (`SYSTEMONE_BASE_URL`); the text helper
  is independent and can be a hosted model.

## Prerequisites

- **Windows 10/11.** The launchers are `.bat` files that call PowerShell.
- **An NVIDIA GPU with a working CUDA driver.** The checkpoint is ~9 GB in
  bfloat16, so it needs a card with room for it alone.
- **Python 3.12 or newer** for the model server (tested on 3.14).
- **`uv`** for the Jev checkout (`uv 0.8.15` at the time of writing).
- **Google Chrome**, for the agent to drive.
- **The Intern-Decision-4B checkpoint**, on disk (see below).

## Setup

### 1. Get the checkpoint

Download `internlm/Intern-Decision-4B` and place it at `D:\models\Intern-Decision-4B`
(or any path you set `MODEL_DIR` to). The directory must contain `config.json`
and `inference.py`; the server imports `DecisionEngine` from it.

```powershell
pip install "huggingface_hub[cli]"
huggingface-cli download internlm/Intern-Decision-4B --local-dir D:\models\Intern-Decision-4B
```

### 2. Create the model-server environment

The server needs `torch`, `transformers`, `fastapi` and `uvicorn` (plus
`Pillow` for image inputs). Any Python 3.12+ environment with those works:

```powershell
python -m venv D:\vpy314
D:\vpy314\Scripts\python.exe -m pip install torch torchvision transformers fastapi uvicorn pillow
```

`start_intern_decision.bat` expects the interpreter at `D:\vpy314` by default;
override it with `set VENV=<path>`.

### 3. Start the decision model

```bat
start_intern_decision.bat
```

The script stops anything already listening on the port, checks that the checkpoint
and the interpreter exist, prints example calls, then serves the model. The first
load builds the CUDA context and prints `loaded in <seconds>` and a `gpu:` line
when the model is ready.

Override any of these before running:

```bat
set MODEL_DIR=D:\models\Intern-Decision-4B
set VENV=D:\vpy314
set DEVICE=cuda:1
set PORT=8011
```

`DEVICE=auto` (the default) picks the visible GPU with the most free memory. The
9 GB checkpoint does not fit beside another copy on a 10 GB card, so the emptiest
card wins.

### 4. Verify the model server

```powershell
curl.exe -s http://127.0.0.1:8011/health
curl.exe -s http://127.0.0.1:8011/v1/models
```

### 5. Set up Jev Ultrafast

```powershell
cd jev-ultrafast
uv sync
Copy-Item .env.example .env
```

Edit `jev-ultrafast\.env` to point Jev at the local model:

```dotenv
SYSTEMONE_BASE_URL=http://127.0.0.1:8011/v1
TYPESAFE_API_KEY=
TYPESAFE_MODEL=intern-decision-4b
MODEL_TIMEOUT_SECONDS=300
TEXT_MODEL_API_KEY=<key for the text helper>
TEXT_MODEL_BASE_URL=https://router.fmcv.my/v1
TEXT_MODEL=deepseek-v4-flash
TEXT_MODEL_REASONING=none
```

- `SYSTEMONE_BASE_URL` is the local decision endpoint; `TYPESAFE_API_KEY`
  stays empty because this server needs no credentials.
- `TYPESAFE_MODEL` is the name sent in the request; the server accepts any.
- `MODEL_TIMEOUT_SECONDS` is raised well above the 25 s default because a
  local forward pass on a full page is slower than the hosted endpoint.
- `TEXT_MODEL_*` is the independent helper that writes `TYPE_TEXT` values.
  Without it a run that needs to type a value fails with a clear error.
- `THINKING_CONFIDENCE_THRESHOLD` (0.7 by default) hands a field the local
  model is unsure about to the text helper; set it to `0` to keep every local
  answer.

### 6. Start Chrome with remote debugging

```bat
ChromeDebug.bat
```

This opens Chrome with `--remote-debugging-port=9222` and a dedicated profile at
`%USERPROFILE%\chromedata`, so the agent does not touch your everyday profile.

### 7. Run the stack

Three terminals, in this order:

1. `start_intern_decision.bat` -- the decision model on `:8011`.
2. `ChromeDebug.bat` -- Chrome on `:9222`.
3. `start_jev.bat` -- Jev, which checks the model and Chrome first.

`start_jev.bat` stops any running jev, waits for the model's `/health` to answer,
hands Chrome's browser-level WebSocket URL to Browser Harness through `BU_CDP_WS`,
and runs `uv run jev`. Open **http://127.0.0.1:8766**, type a task, and click
**Start demo**. The inspector shows numbered elements, operation and target
probabilities, the decision's deliberation, and the executed actions.

## API

All routes return vLLM's error shape: `{"error": {"message", "type"}}`.

### `GET /health`

```json
{"status": "ok"}
```

### `GET /v1/models`

An OpenAI-shaped model list with the one local model.

### `POST /v1/systemone`

Jev's request body: `{"model", "state", "questions"}`. `state` is any text or
JSON value. `questions` maps an id to `{"type", "instructions", "criteria"}`,
where `type` is `noul`, `choice` or `score` and the criteria shape follows it:

- `noul`: optional `{"true": ..., "false": ...}` descriptions
- `choice`: option name to description, or `null`
- `score`: an ordered list of levels

Images go ahead of the state, either as multipart/form-data with the JSON body in a
part named `request` and each image as a file part, or as an `images` array of
data URLs or `{"content_type", "base64"}` objects in the JSON body.

One field:

```powershell
curl.exe -s -X POST http://127.0.0.1:8011/v1/systemone -H "content-type: application/json" -d "{\"state\": \"The customer was charged twice and asks for the extra payment back.\", \"questions\": {\"team\": {\"type\": \"choice\", \"instructions\": \"Which team should handle this request?\", \"criteria\": {\"billing\": \"Payments and refunds\", \"delivery\": \"Shipping and delivery\"}}}}"
```

Every field type at once, an image, and an OpenAI-shaped call are printed by
`start_intern_decision.bat` at startup; `body_image.json` and `body_chat.json` are
runnable copies.

An answer takes Jev's shapes:

- `noul`: `{"type", "noul"}`
- `choice`: `{"type", "choice", "probabilities", "confidence"}`
- `score`: `{"type", "score", "legend", "probabilities", "confidence"}`

The response carries this backend's diagnostics alongside:

```json
{
  "model": "intern-decision-4b",
  "answers": {"team": {"type": "choice", "choice": "billing", "probabilities": {}, "confidence": 0.0}},
  "usage": {"input_tokens": 0, "output_tokens": 0},
  "diagnostics": {"backend": "", "timing": {"reads": 0, "total_ms": 0.0}, "prompt_tokens": 0, "calibration": null}
}
```

### `POST /v1/chat/completions`

The same decision from an OpenAI-shaped call. `messages` must be exactly two:
the schema as JSON in the `system` message and the state as JSON (or image parts)
in the `user` message. The answers come back as JSON text in the assistant
message.

### Errors

| Status | When |
| --- | --- |
| `400` | The body is not JSON, or the messages are not the two expected shapes |
| `401` | `API_KEY` is set and the bearer token is missing or wrong |
| `404` | Unknown route |
| `422` | A question or body key is invalid, or a limit is exceeded |
| `500` | The read failed, with CUDA memory failures named and actionable |

## Troubleshooting

**The model server exits with a CUDA out-of-memory error.**
Two copies of the 9 GB checkpoint do not fit on one 10 GB card. Restart with
`start_intern_decision.bat`, which stops the old server and picks the emptiest GPU.
Do not set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`: on a card this
full a segment that cannot grow fails with `cuMemSetAccess` and leaves the
allocator unable to release blocks. The plain allocator fails cleanly instead, and
the server retries once after emptying its cache.

**`start_jev.bat` reports no decision model.**
Start `start_intern_decision.bat` first and wait for `/health` to answer.

**`start_jev.bat` reports no remote debugging.**
Run `ChromeDebug.bat`, and allow remote debugging in Chrome when prompted.

**Jev returns `No target with given id found` and stops.**
Chrome closed the tab Jev was attached to (it closes background tabs, and a daemon
restart does it too). Jev now detects this, opens a fresh tab, and carries on; if you
are on an older checkout, restart `start_jev.bat`.

**Jev's first decision takes a long time.**
A local forward pass on a full page is slower than the hosted endpoint. Raise
`MODEL_TIMEOUT_SECONDS` and expect the first read to include the load.

**A run that needs to type a value fails.**
`TEXT_MODEL_API_KEY` and friends are required for `TYPE_TEXT`; the decision model
only chooses an operation and an element.

**The inspector shows the model on a different port.**
The tag in the header and the footer come from `/api/state`, which reads
`SYSTEMONE_BASE_URL` and `TEXT_MODEL_BASE_URL`; check the `.env` Jev loaded.

## Known limitations

- The local model is usually less confident than `THINKING_CONFIDENCE_THRESHOLD`
  (0.7), so the text helper decides most fields. Set the threshold to `0` to keep
  every local answer, or to a lower value to hand over less.
- The checkpoint is a vision model, but `choose()` sends text only. Attaching the
  screenshot does reach the model and shifts the distribution a little, but the
  operation is still decided from the text.
- The scenario fixtures are small local pages. Match the goal to the scenario: the
  `travel` fixture is stays, not flights.
